# 复盘：我（DSH）在这类项目里常犯的错，以及能自动拦住的护栏

证据来源：本仓库 git 历史、本次会话中回滚/返工记录。不含推测。

## 一、错误分类与实例

### A. 用便利操作代替精确操作（最高频）

| 实例 | 后果 |
|---|---|
| `git add -A` 3 次 | 把 Codex 在写的文件混进我的 docs 提交（图标、编号方案两次） |
| `str.replace` 用非唯一锚点（`{readOnly ? (`，3 处） | 状态插进 3 个组件、JSX 一处没进，**`tsc` 仍通过**，部署了一段死代码 |
| 按行号切片抽模块（2 次） | `App.tsx` 被切碎，`tsc` 报一串语法错，回滚 |

**根因**：在大文件上做机械化文本操作，把"能改"当成"改对了"。

### B. 整行替换导致静默丢字段

`refund-operations.ts` 里把
`refundId, billId, assetId, currency,` 整行换成 `refundId, billId, bookId,`，
**顺手删掉 `assetId`/`currency`**。类型是可选的，`tsc` 不报；测试立刻报 `undefined !== 31`。

**根因**：只想着"要加什么"，没核对"这一行原来有什么"。

### C. 用 `Date.now()` 当唯一 ID

- `reimbursementId`：同毫秒两笔报销撞号 → 点"确认到账"一次结清两笔，账户多进钱
- `lendId`：父借贷与还款记录撞号 → 剩余额算错

两次都是**允许多笔之后才暴露**，单笔场景永远测不出来。

**根因**：把"时间戳"当成"唯一"，忽略了同一毫秒内的多次创建。

### D. 结论未经复核就宣布

| 我说过的 | 实际 |
|---|---|
| "导入导出 95%，缺 JSON 导出" | JSON 导出**早就有了**，还有完整往返测试 |
| "统计页截断没做" | 人家改的是网格列宽，我看错了位置 |
| "键盘你还没定 A/B" | Codex 早已实现并有测试 |

**根因**：用记忆和 grep 片段替代读代码；把"我记得"当成"我确认"。

### E. 验证信号读错

- `npm run test | tail` → 退出码是 `tail` 的，测试失败显示成功
- `timeout npm run check` → MSYS 下恒返回 126，我一度当成构建失败排查半天
- 负向测试用管道，`probe exit=0` 是假的

**根因**：没有"直接取退出码"的习惯。

### F. 修复后没验证"另一侧"

分类去重连试 3 次才生效，前两次都是"我以为改了"，实际：
1. 去重后数组变短，但变更检测只比前 N 项 → 判定"无变化"
2. 同步又把云端旧分类灌回来 → 去重被覆盖

**根因**：只验证"我改了代码"，没验证"结果真的变了"。

### G. 交付前没冒烟

插入位置错误的"最近记账"块，`tsc` 通过、构建成功、**部署上线**，页面上什么都没有。

**根因**：把"构建成功"当成"功能可用"。

## 二、根因归纳

| 根因 | 表现 |
|---|---|
| **在大文件上用文本手术** | A、B、F |
| **改动的自我审视缺失** | A、B（不看 diff 就提交） |
| **把记忆当证据** | D |
| **验证不闭环** | E、F、G |
| **乐观命名** | 单笔场景设计、`Date.now()` 唯一性 |

## 三、护栏

### 已落地（自动拦截）

| 护栏 | 拦住了什么 |
|---|---|
| CI：typecheck / test / icons / tokens / contrast / lint / build | 任何一项不过，PR 红 |
| `noUnusedLocals` | 死代码、死导入（一次抓出 12 处） |
| `no-explicit-any: error` | 随手写 `any` |
| `ui-tokens.mjs` | 颜色/圆角/字号字面量（拦住我两次写兜底色） |
| 235 条测试断言 | 丢字段、撞号、越界（本次抓到 4 个真 bug） |
| `icons:check` | 图标引用缺失/孤儿 |

### 本次新增（操作纪律，写成脚本）

1. **`scripts/guard-staged.mjs`** —— 提交前检查暂存区：
   - 禁止 `.tmp/`、`dist/`、`server/data/`、`.env`、`*.credentials*`
   - 打印将要提交的文件清单，多文件时要求显式确认
2. **`npm run hooks:install`** —— 安装 git pre-commit 钩子，自动跑上面那条

### 待落地（需要我改习惯，工具只能辅助）

| 纪律 | 具体做法 |
|---|---|
| **禁止 `git add -A`** | 只 `git add <具体路径>`；提交前先 `git status` 看清单 |
| **批量替换必须断言唯一** | `assert s.count(anchor) == 1` 才动手 |
| **禁止行号切片** | 一律用标记定位（唯一字符串） |
| **只追加，不整行替换** | 需要改整行时，先看原行内容，改完立刻跑测试 |
| **唯一 ID 走工厂** | 业务代码禁止直接 `Date.now()` 做 ID；统一 `newId()`（时间戳+自增+随机） |
| **声称"缺功能"必须给证据** | 必须提供 `文件:行`，否则写"未核实" |
| **退出码直接取** | `cmd > log 2>&1; echo $?`，不用管道后的 `$?` |
| **交付带两栏** | 「已验证」/「未验证」分开写 |

## 四、一句话结论

我的错误**不是"不会写"，而是"手太快、验证太晚"**——
在大文件上做机械化操作、用记忆代替读代码、把构建成功当成功能可用。

自动化护栏已经把**能被机器判定的部分**都堵住了（类型、死代码、令牌、测试、CI）；
剩下的是**操作纪律**，需要我自己在动手前多停一秒。
