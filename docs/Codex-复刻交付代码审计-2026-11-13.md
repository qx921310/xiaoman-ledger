# 复刻交付代码审计（2026-11-13）

审计基准：`912a5b6`；以 `9d3e685..912a5b6` 的 38 个提交和受影响的同步、余额、备份、搜索、统计、资产、借贷为重点。没有操作生产或 staging，没有对整份 APK 的业务状态逐条验收。下列“本地复现”均为隔离内存状态或临时测试数据。

**结论：不建议按「已完成 1:1 复刻、可直接上线」验收。** 布局资源、控件 ID 和文案能证明存在入口，不能单独证明数据模型、操作语义、权限、异常路径及结果与原应用一致。以下问题足以阻挡涉及真实财务数据的上线。

## P1：数据与资金正确性

### 1. 三类新增实体与自身云端记录合并会生成副本

位置：`src/store.ts:501`、`:521`、`:535`；`src/domain/sync-merge.ts:119`、`:132`。

定存、智能分类、愿望的本地构造都没有 `ownerId` / `userId`，云端拉取时合并代码会补 `ownerId`；同 ID 比较时本地属主为 0，云端属主为 1，被当成不同属主后改号插入。对已创建本地记录调用 `applyRemote`，分别复现 `dream 2`、`aiType 2`、`fixedDeposit 2`。这证明合并动作有问题，不等于已在生产复现整条自动同步链路。

建议：按真实作用域统一身份与属主规则，回归覆盖本机推送后拉回、另一设备重复拉取、修改、删除、同 ID 不同账本及历史副本恢复；不能直接把所有新实体一律设为无属主而忽略多人账本权限。

### 2. 新增的愿望、分类规则、定存不在 JSON 备份中

位置：`src/store.ts:1350`、`:1619`；`src/backup.ts:44`。

隔离 store 各创建一条后调用 `exportAll()`，三个数组均存在于状态，但导出结果均无 `dreams`、`aiTypeRules`、`fixedDeposits`。导入路径也没有恢复它们。全新设备用该备份恢复无法找回这三类信息，尽管它们已接入云同步。

建议：扩展备份格式、校验、导入与版本兼容，并在全新空状态做导出→恢复断言；不要将同步元数据视作业务数据备份。

### 3. 跨账本还款写入当前账本而非原借贷账本

位置：`src/store.ts:1137`、`:1166`。

本地复现：在 A 创建借出，切换 B 后对 A 的借贷执行 `repayLend`，父记录 `bookId=A`，还款记录 `bookId=B`。清空 B 或按账本查看时会破坏或隐藏还款关联；还款也影响账户余额。

建议：让还款继承并校验原借贷的账本；新增“全部账本”视角时先要求明确归属。测试跨账本还款、删除与两端余额。

### 4. 新增三类实体删除时墓碑绑定当前账本

位置：`src/store.ts:515`、`:529`、`:549`。

在 A 创建记录、切换 B 后删除，删除动作从 `currentBookId` 而不是被删除记录取得 `bookId`。服务端可能判 `scope-conflict`，本地看似删除但跨设备不收敛；处于“全部账本”时又会缺少代次。建议从目标记录继承作用域，并对跨账本及离线删除补回归。

### 5. 模板可绕过账本、账户和记账校验

位置：`src/store.ts:650`；入口 `src/features/templates.tsx`。

本地复现：模板在账本 A 创建，切换到账本 B 后一键执行，返回成功且账单 `bookId=B`。该入口直接调用 store，不经过 `src/features/add-bill.tsx:96` 的具体账本、账户、共享账户和金额校验；账户已删除时还可能写入无效账户。

建议：抽取统一的业务命令校验，处理模板所属账本及当前账本不一致、只读权限、账户有效性、币种及金额；先让用户可见目标账本和账户。

### 6. 同步冲突可能显示为已同步

位置：`src/sync-auto.ts:60`、`src/App.tsx:62`、`src/features/settings.tsx:163`、`:473`。

调度器已计算 `incomplete`，但设置页状态文案只检查 running/error/pending/lastOkAt，不检查 incomplete；启动警告读取 `denied` 和 `conflictsKept`，而 v2 runner 的实际冲突在 `conflicts`。有本机待核对草稿时页面可能只显示上次同步时间。建议以 `incomplete`、`blocked` 和冲突为权威状态，在所有入口明确提示并提供处理入口。

### 7. 自动补“现金”仍把同步失败当成已完成

位置：`src/App.tsx:160`、`:164`；`src/sync.ts:290`。

失败时 `sessionSyncAt=-1`，但 `if (!synced) return` 不会拦截 -1，因此资产空且首次拉取失败时仍创建现金。恢复网络后若云端已有账户，仍可能出现重复。另有两台空设备同时成功拉取、各自创建的竞态。

建议：区分成功、失败和未开始，不能仅依赖真值；新设备创建采用服务端幂等身份或其他跨设备唯一方案。测试失败后恢复及并发首次登录。

## P2：功能闭环和结果可信度

### 8. 智能分类只管理规则，没有执行规则

位置：`src/features/ai-type.tsx`、`src/store.ts:521`。

全文检索 `aiTypeRules`，除读写、同步映射外没有记账、导入或识别环节消费关键词。界面却显示“关键词命中时自动归到对应类别”。建议明确触发场景和优先级，接入执行链并测未命中、多规则、收支方向与人工更改。

### 9. 资产走势用当前资产倒推历史，口径不成立

位置：`src/features/stats.tsx:61`。

当前代码把不同币种的 `assetNumber` 直接相加，以现在余额为所选区间最后一点，只减去区间内账单收支。历史区间之后的交易、转账手续费、借贷、退款实际发生时间、调整期初、汇率变化及账户纳入范围都可能影响净资产；跨年时 `M/D` 标签还会合并不同年份。图形是可计算出的数字，但无法作为实际资产历史。建议基于有日期和币种的资产流水、汇率与账户范围重建，缺乏历史证据时明确标为估算或不展示。

### 10. 定存到期日按固定 365 天，且没有资产流水闭环

位置：`src/features/fixed-deposit.tsx:18`、`src/store.ts:501`。

到期日使用 `startTime + 年数 × 365 天`，跨闰年会错一天，夏令时地区也可能偏移；新增只保存独立记录，没有要求账户或产生资金变动。未证实一木定存的具体记账语义，因此只能判断当前功能与“资金账户闭环”之间的差距，不能据此断言原产品如何处理。建议按产品规则明确到期与是否产生转账，并覆盖闰年。

### 11. 搜索命中后没有打开账单详情

位置：`src/App.tsx:203`、`src/features/search.tsx:161`。

点击搜索结果仅关闭搜索，传入的账单 ID 被忽略；也不会定位到该账单。建议传递身份并打开现有账单详情，测试跨月份、已删除账单及重复 ID。

### 12. “全部 / 按月”与账单组筛选存在缓存遗漏

位置：`src/features/bills.tsx:115`、`:119`、`:145`。

筛选闭包依赖 `rangeAll`，但 `list` / `tList` 的 `useMemo` 依赖数组没有该值；分组列表也没有搜索、金额、日期等筛选依赖。仅切换菜单或筛选时可能继续展示旧结果，或把组内不匹配项一起展示。建议补完整依赖并测试无需改变其他状态的连续切换。

### 13. 资产设置“生效账本”无法表达全部隐藏

位置：`src/features/assets.tsx:877`；`src/domain/asset-scope.ts:14`。

空数组被解释为“所有账本可见”；取消最后一个账本时也写空数组，随即又变为全部可见，单账本下更是无法取消。建议区分“全部”和“无”，并迁移旧存储格式。

### 14. 手势密码是本地明文 PIN，且没有后台重锁

位置：`src/features/lock.tsx:3`、`:23`；`src/App.tsx:24`、`:137`；`src/features/settings.tsx:560`。

四位 PIN 明文存 `localStorage`，同浏览器所有账号共用，关闭时只确认、不核验 PIN；解锁后切后台/切回没有重新置锁。它只能提供弱的界面遮挡，不具备设备或账号安全锁的保障。建议明确产品定位，至少增加重新验证、账号隔离和失败策略；不要宣传为可保护浏览器本地数据的安全边界。

### 15. 统计视图及隐藏预算未达到交付描述

位置：`src/features/stats.tsx:195`、`:56`、`:113`。

交付清单称四视图，实际 tab 只有“普通 / 年度 / 自定义”三项，周是另一个 select；月度视图并非独立 tab。隐藏过滤只用于月预算，年预算与自定义预算仍未过滤 `hide`。建议按真实功能定义验收并补对应页面交互测试。

### 16. 首页月汇总仍使用 UTC

位置：`src/features/home.tsx:28`、`:33`。

页面标题用本地月份，而数据按 `toISOString()` 的 UTC 月份分组；东八区每月 1 日 00:00–07:59 会把当前月份与本地月份错开。建议统一使用 `monthOf` 等本地日期规则，测试跨月。
