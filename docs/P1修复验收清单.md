## 四、仍未解决（诚实列出）

1. **`localeCompare` 已改为显式字符序**（本轮顺手修了 #3 的比较），但没有跨大小写 UUID 的专项测试。
2. **历史数据迁移**：被错误改写的「其他」分类账单、历史退款/报销的 `bookId` 仍无迁移脚本。
3. **#4/#5/#7 只做了代码层验证**，没有双账号/双设备端到端。
4. **#2 的 3 秒宽限**仍存在：在线慢网超过 3 秒会提前生成。
5. **#6 的取舍**：不静默绑定意味着旧规则在生成前 `bookId` 为空，多设备同时生成仍可能落到各自当前账本。要根治必须在服务端分配。
