# 第八轮复审：移动网页（2026-11-13）

审计基准 `5df7c0e`，对照 `c956234`。复核账号切换、报销、预算、分类、账本补传及资产走势；使用隔离数据，没有操作生产或 staging。**结论：不能验收通过。**

## P1：外币报销完成后，原币余额会随汇率变化

`src/balances.ts:48` 每次重算余额都以当前汇率将历史报销本币金额换算；`src/store.ts:231` 将当前 currencies 注入推导，`setCurrencyRate` 又触发重算。隔离实测：720 CNY 报销到 USD 账户，汇率 7.2 时余额是 100 USD；仅把汇率改为 8，没有发生任何资金交易，USD 余额就变成 **90 USD**。此外 `src/domain/account-history.ts:77` 和 `src/domain/asset-trend.ts:78` 仍把 720 当 USD 流水；同一复现中账户余额 100，账户流水结余却是 720。

建议在报销确认到账时持久化账户币种、实际到账原币金额、本币金额和汇率快照，并让余额、流水与走势共用该快照；汇率缺失不能回退 1:1。测试部分/多次报销、汇率修改、历史数据迁移、刷新及跨设备。当前改动虽修正了固定汇率下的 720→100，但没有闭合整个资金模型。

## P1：预算删除墓碑和新同步 ID 不匹配

`src/sync.ts:56` 的预算 ID 已改成 `type:month:categoryId` 或 `custom:budgetId`，但 `src/store.ts:1393`、`:1412` 产生的删除墓碑仍为 `type:categoryId` 或纯 `budgetId`。隔离实测周预算创建记录 ID 为 `week:all:7`，删除产生墓碑 ID 为 `week:7`。因此该墓碑不会删除同一云端身份，后续同步可重新拉回旧记录。自定义预算同理，历史旧身份迁移也需单独处理。

建议将身份生成抽为唯一公共函数，创建、删除、合并、同步和迁移均使用同一规则；对历史 ID 做兼容映射或带墓碑迁移。以真实双客户端测试增删、旧数据升级及不复活。

## P1：账本补传进行中，新入队操作被删除

`src/features/book-pending.ts:74` 读整个队列到局部变量，等待网络后 `:92` 将该旧快照整体写回。隔离复现：A 的更新正在补传，期间 B 的新修改入队；A 请求成功后，队列变成空，B 未发送且不再待处理。并发补传和同账本二次编辑也有同一竞争窗口。

该函数收到版本冲突时 `:86` 直接删除本地草稿；调用方未显示 dropped，违背此前明确的“冲突保留并提示核对”。队列使用全局 key，缺少账号作用域；空基准版本仍会绕过服务器版本保护。建议按用户隔离并串行处理，给每次操作稳定 ID，网络返回后重新读取并只确认相同操作；冲突保留原值、明确提示核对。涵盖断网、在途新编辑、双标签、切账号、版本冲突和重启。

## P1：账号加载无条件丢弃期初余额

`src/account-session.ts:29` 对每次加载的每个资产都移除 `openingBalance`，改以持久化的 `assetNumber` 和流水反推。用户已确定期初余额是同步的权威字段，assetNumber 是派生缓存；一旦旧缓存与流水不同步，例如恢复旧备份或同步尚未完整时，重新登录就会把缓存误认为真实余额，重写期初。上轮提供的跨账号样本本次已恢复 100 / 100，但它不能证明这种新迁移方式安全。

建议仅当期初确实缺失且能证明缓存与流水来自同一快照时进行一次性迁移；现有有效期初应保留，余额从目标账号数据推导。回归覆盖有效期初与过期缓存、历史缺期初、损坏快照及跨设备恢复。此项为代码路径和模型分析，尚未证明具体生产数据受到影响。

## P2：分类二级作用域和其他遗留问题

- `src/features/add-bill.tsx:27` 大类已使用 `hideBook`，但 `:29` 二级分类仍仅检查全局 `hide`。恢复某大类或单独隐藏某子类后，该账本下被隐藏的子类仍可见；另一账本的子类不再被全局隐藏。
- 汇率走势对已完成报销仍按本币数字作为账户原币变动，且没有历史汇率和账户创建/手动调整事件，不应无条件称为真实历史。
- 账本图标的本地旧值覆盖服务器值、资产流水缺账本代次、上传失败提示和图片压缩等上轮遗留项未在本轮证明解决。
