## 阻断与高优先级

### P0-1 有账户时记账页白屏（基线复现；工作区有修复待复测）
- `src/features/add-bill.tsx`：基线在 `aid` 初始化前对非空账户数组执行 `find` 并读取它。隔离浏览器点击「添加一条新记账」，页面空白，控制台 `ReferenceError: Cannot access ... before initialization`。基线还把 `useRef` 放在移动端条件分支，切换视口有 Hook 顺序风险。
- 建议：先声明状态，Hook 移到顶层；补有账户/无账户、320/390/桌面及横竖屏切换的生产构建浏览器测试。审计中观察到工作区已移动变量和 Hook，需固定版本重新验证。

### P1-1 切账号后上一用户数据残留
- `src/App.tsx` 的新账号初始化调用 `reset()`；`src/store.ts` 的 reset 未清空 tags、currencies、tombstones、accountBooks 等，持久化 rehydrate 不能保证无旧状态。模拟先创建 A 的私有标签，再切至无本地数据 B 并执行 reset/rehydrate，B 仍看到 `private-tag`；随后自动同步可能将其写入 B。
- 建议：以完整初始快照重建内存，再按账号恢复；同步任务绑定会话代号，阻止旧账号异步请求跨会话写入。测试已有/无本地数据两类账号切换及云端拉取。

### P1-2 附件跨账号访问
- `server/server.mjs` 的 `/uploads/` 只判断已登录。隔离服务测试：A 上传虚拟 PDF，互不关联的 B 拿到链接后读取返回 200；匿名为 401。链接在共享、日志或退出账本后可能泄漏，不能以路径难猜替代授权。
- 建议：服务端持久化文件归属、关联账单与账本；按实际成员权限授权，退出后撤权，私有附件仅属主可读；测试非成员、成员、退出、匿名、伪造关联。校验真实文件类型，清理无主附件。

### P1-3 资产隐私与默认账本限制（基线复现；工作区有修复待复测）
- 基线 `src/domain/asset-scope.ts` 将所有非 0 账本视为多人账本，私有账户在单人账本也被阻断；手机「再记」和桌面提交未经过同一校验。审计中工作区已引入成员数和统一提交校验，但 `src/App.tsx` / `settings.tsx` 的账本映射需确认保留后端 `memberCount`，未知成员数及离线场景不能假定安全；转账的两个账户也需覆盖。
- 建议：服务端按账本成员和账户归属保护真实数据；所有入口共用校验，测试单人、多人、离线未知、两种按钮、桌面和转账。

### P1-4 清空账本后旧数据会复活
- `server/server.mjs` 的 `/api/books/clear` 直接 DELETE records；隔离服务测试：清除 1 笔后重放另一设备仍保存的旧记录，服务端接受且账单重新出现。设置页提示本机清空无法保证所有离线设备同步。
- 建议：按账本引入清空代次/服务端墓碑或等效版本屏障；拒绝或提示旧代次写入，明确离线修改冲突与恢复流程，测试多成员、断网重连和旧设备重放。

### P1-5 同期冲突可能使云端无有效账单（既有、仍需端到端解决）
- `server/server.mjs` 的 periodKey 去重仅返回计数；`src/sync.ts` 没处理候选回执且仍用本地排序删重复。隔离服务复现：服务端接受 z、拒绝 a；客户端按字符序保留 a、给 z 写墓碑；下一次 a 仍被拒而 z 被删，服务端只剩 z 的墓碑。
- 服务端还信任客户端期号，省略期号可绕过；删除或清空账本没有清理/重新定义 period 占用。迁移、跨时区、历史客户端均需覆盖。
- 建议：服务端验证并原子分配业务期号，逐条返回权威 ID 和 created/existing/conflict；客户端只据回执处理未编辑候选，有关联或差异保留核对；明确删除、恢复、改期、清空生命周期和旧客户端兼容。

### P1-6 同一身份模块未贯穿所有合并分支（既有）
- `src/domain/sync-merge.ts` 普通记录仍按原编号选 idx、按属主判断碰撞，未统一比较账本作用域。模拟同一属主、A/B 两账本同编号转账，合并 B 后 A 被覆盖。未知作用域墓碑在 `!== false` 分支会挡住另一账本有效记录。
- 建议：记录/墓碑/冲突改号全链路使用 `(scope,kind,businessId)`，未知身份保留并提示，不作覆盖/屏蔽；测试到达顺序、跨账本同 ID、缺作用域、重复墓碑及关联引用。

### P1-7 自定义预算与月预算互相覆盖
- `src/store.ts:setBudget` 仍用 `(month, categoryId)` 做唯一键，统计页各种预算均可写 `all`。模拟总月预算 1000 后写同分类自定义预算 200，只剩自定义预算；多个同分类自定义预算也不并存。
- 建议：自定义预算用独立 UUID；月/年预算用周期+分类区分，删除墓碑和 `src/sync.ts` 的预算身份一起迁移；测试创建、修改、删除、跨设备和旧数据兼容。

### P1-8 账户流水不等于真实余额（基线手续费复现；工作区有修复待复测）
- 基线 `src/domain/account-history.ts` 对独立手续费账单重复计算手续费：期初 1000，转出 100，手续费 2，真实余额 898，流水显示 896。工作区已加手续费分支。
- 仍需核对退款：`balances.movements` 只有关联账单存在才入账，并支持旧退款缺 `assetId` 时回退到账单账户；当前工作区历史流水对有 `assetId` 的孤儿退款直接入账、对无 `assetId` 的旧退款跳过。模拟孤儿退款 3，真实余额 100，流水 103。
- 建议：两者复用同一资金流水来源；对孤儿和旧记录统一处理，测试关联手续费、无关联手续费、退款跨账户、孤儿记录和外币，断言流水末余额=资产余额。

### P1-9 导出 Excel 的账本名称可能错误
- `src/importer.ts:buildExportTable` 用 `accountBookId === b.bookId` 找账本，服务端真实账本 ID 在 `bookId` 字符串。隔离样例账本名为 daily，导出账本列却回落为「日常账本」；再次导入可能误入账本或被跳过。
- 建议：统一 `String(bookId ?? accountBookId)` 匹配；无法确定或同名时提示，不伪造默认名。测试多个服务端账本 Excel 往返及 JSON 完整备份。

### P1-10 共享账本转账没有账本作用域
- `src/store.ts:addTransfer` 创建 Transfer 未写 `bookId`，同步以个人记录发送；隔离状态测试选中 group-A 后新转账 `bookId === undefined`。无手续费时删除墓碑也无法借手续费账单获得账本，`Bills` 会在其他账本显示无作用域的转账。
- 建议：明确转账归个人还是账本；如是账本记录，创建/编辑/删除/导入均携带稳定 `bookId` 和身份，服务端授权并处理旧记录待核对。测试共享成员、跨账本切换和无手续费。
