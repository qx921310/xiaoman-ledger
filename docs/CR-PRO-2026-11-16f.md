问题列表：

- 级别：P1
  位置：src/store.ts:addBill 内的 bookId 分支
  现象：当 currentBookId === 0（“全部账本”/未选账本）时，addBill 计算得到 bookId = undefined，随后的只读检查被 `if (bookId != null)` 跳过，最终写入 bookId = 0 的无归属账单。如果账本列表中存在历史只读账本（role=silent），该路径可绕过只读限制产生脏数据，且该账单很可能在任何账本视图下不可见。
  复现要点：
  1. 账号下同时存在可写账本与只读账本；
  2. 将当前账本切到“全部账本”（currentBookId=0）；
  3. 打开记账页记录一笔支出；保存成功，但账单 bookId 为 0，而不是指定账本，且未触发只读校验。
  修复建议：即使 bookId 为 undefined，也应采用保守策略：若 accountBooks 中存在 silent 账本则拒绝，或强制要求调用方显式传入可写 bookId；不要在 bookId == null 时完全跳过权限检查。

- 级别：P2
  位置：src/features/assets.tsx:486（AssetEditor onSave，以及新增账户保存处）
  现象：新增/编辑/删除资产的 store 命令（addAsset/deleteAsset/updateAsset）现在在只读账本下会静默 return {}，但 UI 不检查返回值，仍执行 `setEditingAsset(null); notify('账户已更新')` 或类似成功提示。用户以为保存成功，实际状态未变更。
  复现要点：
  1. 在只读账本中打开资产页；
  2. 点击账户进入账户流水页，点“编辑”并改余额后保存；
  3. 界面提示“账户已更新”，但重新进入账户后余额未变。
  修复建议：让 addAsset/deleteAsset/updateAsset 返回 boolean；调用处检查返回值，失败时提示“当前账本只读，不能修改”；或在进入编辑/新增前禁用入口。

- 级别：P2
  位置：src/features/calendar.tsx:169-190（monthDayGroups 计算）
  现象：月历日列表的日支出合计使用 `billNetAmount(b, refunds)`（扣除退款的净额）。当退款发生在另一天时，原支出日的支出被低估，退款日也没有对应冲回记录，导致日收支合计在跨日退款场景下不守恒。
  复现要点：
  1. 1月1日记支出 100 元；
  2. 1月5日对该账单退款 30 元；
  3. 日历月列表显示 1月1日支出 70 元，1月5日无退款收入/负支出，整月合计仍可能正确但单日合计口径不一致。
  修复建议：若产品口径是“退款冲减原账单”，则日合计应使用原始支出；若口径是“退款计入退款日收入”，则应在退款日生成对应收入行。统一口径后再计算日合计，避免用净额直接计入原日。

- 级别：P2
  位置：src/features/stats.tsx:180-189（assetPie）
  现象：资产汇总饼图过滤 `Number(a.assetNumber) > 0`，所有负余额账户（如信用卡负债）被直接隐藏。资产汇总只显示正资产，不显示负债，用户会误以为负债不存在。
  复现要点：
  1. 添加一个信用卡账户，余额为 -2380；
  2. 进入统计页查看“资产汇总”；
  3. 饼图和图例中完全没有该信用卡。
  修复建议：根据产品需求决定是否将负债单列或按绝对值展示；若需完整资产汇总，应包含负余额或单独显示负债项，而不是静默过滤。

- 级别：P2
  位置：src/store.ts:1873-1877（updateAsset 迁移拒绝）
  现象：新增的账本归属校验要求 `String(asset.bookId) === String(existing.bookId ?? '')`。如果旧资产 existing.bookId 为数字（本地账本），而 AssetEditor 或其他调用方传入的 asset.bookId 是等值字符串，或 existing.bookId 为 undefined 而传入 currentBookId，会触发拒绝。正常编辑旧资产可能失败且无提示。
  复现要点：
  1. 从旧版本导入/迁移一个 bookId 为数字的账户；
  2. 修改账户名称或余额后保存；
  3. 保存无效，余额不变，但 UI 可能提示成功（与上一条叠加）。
  修复建议：比较前先做类型归一化，例如 `String(asset.bookId ?? '') !== String(existing.bookId ?? '')`，并且如果 AssetEditor 总是带出原 bookId，需确认类型一致；同时让 updateAsset 返回失败状态供 UI 提示。

- 级别：P2（待确认）
  位置：src/features/bills.tsx:378-381（账单行点击）
  现象：simpleView 下账单行点击无条件 `setDetail(b)`，未检查 readOnly。只读账本下用户仍可打开详情，若详情弹窗内的编辑/删除/退款按钮未根据 readOnly 禁用，会暴露不可用或误操作入口（最终 store 命令被拒绝但也可能误提示）。
  复现要点：
  1. 在只读账本中打开首页账单列表（simpleView=true）；
  2. 点击任意账单行，进入详情；
  3. 详情中是否出现“编辑/删除/退款”按钮取决于后续组件，若有且未禁用，则可误操作。
  修复建议：在 `setDetail(b)` 前或详情组件内部统一判断 readOnly，只读时仅展示只读详情，不渲染任何写操作按钮，或点击时提示只读。
