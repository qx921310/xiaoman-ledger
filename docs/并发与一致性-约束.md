# 并发与一致性：已定约束（改这块前请先读）

## 1. 不存在真正的并发写入

每个用户先写自己的本地库，**只有同步时才合并**。服务端按 `(user_id, kind, rid)` 分行存储。
所谓"并发"只发生在 **合并阶段**，不是数据库竞争。

## 2. 记录身份：ID + 属主

- `billId = 秒级时间戳 × 1000 + (userId % 1000)`（记账 / 周期生成 / 导入三处一致）
- 合并时同 ID 不同属主 → **不覆盖，顺位另存**（`applyRemote`）
- 服务端权威：说了算的是服务端，客户端不自行发明身份

## 3. 余额不是字段，是推导结果

- `assetNumber` 是**本地显示缓存**，可在任意时刻由 `openingBalance + 流水` 重算
- 同步**不推送** `assetNumber`，只推 `openingBalance`
- 任何 `set` 都会重跑 `deriveAssets`
- 余额变化**不改 `updateTime`**，避免制造假更新、抢别人的记录
- 不变式：`直接突变后的余额 === deriveAssets(期初 + 全部流水)`，已被单测覆盖

## 4. 删除必须写墓碑

- 账单、转账（含其手续费账单）、借贷、周期、报销、退款、预算，删除都要写墓碑
- 收到墓碑时**先比对本地的 `updateTime`**，本地更新则忽略
- 墓碑权限由服务端按已有记录反查账本后校验（非成员 / 静默一律拒绝，改他人记录需 admin）

## 5. 不能破坏的既有行为

- 转账本金不计收支；手续费单独成账单，`净资产只减少手续费`
- 报销两段式：登记不动钱，确认到账才进报销账户
- 借出/借入直接冲账户、不计收支
- 外币 `cost` 存本币，`currencyAssetNumber` 存原币

## 6. 已知未覆盖

- 导入路径（`applyImport`）未纳入余额不变式测试
- 多设备离线并发未做端到端复现
- 服务端历史 payload 里仍可能带 `assetNumber`（客户端会重算覆盖）

## 7. 测试入口

```
npm run test:balances     # 余额推导与 CSV 合成
node .tmp/test-invariant.cjs   # 直接突变 vs 重算 的不变式（9 步操作）
```
