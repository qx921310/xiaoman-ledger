# 第六轮 CR 与修复

审计版本：`e697091`。本轮复验上轮问题后直接修复了仍未闭环的迁移数据保护。

## 已验证

- 账单普通编辑不能再变更账本归属；跨账本 AA 群组引用被拒绝。
- 迁移冲突会保留 scoped / global 两份候选，账本管理支持导出候选。
- 会话代次、重试租约及只读命令守卫的回归仍通过。

## 本轮直接修复

1. 全局旧队列 JSON 无法解析时，迁移流程原先会以空对象覆盖并删除原始键；现在保留原值，供人工恢复。
2. 迁移冲突中的候选在后续编辑入队时会丢失；现在随草稿持久化保留。
3. 增加“使用全局候选”操作：只切换待确认的本地候选，不会自动提交或清理原始草稿；用户仍需点击“保留本地”。
4. 候选备份写入失败时，停止清理旧键，避免数据丢失。

新增 3 条可靠性回归：损坏全局键保留、全局候选选择、备份写失败保留。完整 `npm run check` 通过。

本轮未触及生产或 staging，也未进行真机/微信 WebView 验收。
