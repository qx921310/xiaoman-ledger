- 问题列表：
  - 级别：P1（待确认）  
    位置：src/ui/select-shim.tsx:52-58  
    现象：全局 SelectShim 通过调用原生 HTMLSelectElement 的 value setter 并手动 dispatchEvent(new Event('change')) 来模拟选择。若 React 受控 select 未在该事件下正常更新 state（例如某些浏览器/React 事件委托链路异常），用户所选账户、币种等关键值可能未真正写入状态，导致后续记账以旧值/默认值提交，影响余额正确性。  
    复现要点：在未被 SelectSheet 替换的原生 select 上（如其他未改动页面中的分类/账户选择器）操作，检查对应 state 是否更新；或编写端到端测试验证点击后 onChange 触发。  
    修复建议：改用 React 认可的交互方式（例如直接调用 select 的 onChange 属性）或在 commit 后校验 DOM value 与预期一致；增加端到端回归覆盖关键选择器。

  - 级别：P2  
    位置：src/features/assets.tsx:44-48  
    现象：readOnlyBook 仅基于 currentBookId 判断，当用户处于“全部账本”（currentBookId===0）时返回 false，未禁用任何账户的编辑/删除按钮。虽命令层会拒绝写操作（store.ts bookWritable 对 bookId 0 且存在只读账本时返回 false），但 UI 未提前提示，用户可能误以为操作可用。  
    复现要点：存在一个只读账本和一个可写账本，在资产页切换到“全部账本”，点击只读账本账户的编辑按钮。  
    修复建议：readOnlyBook 判断应基于目标账户的 bookId（或列表数据），而非当前视图的 currentBookId；或在点击时再提示只读。

  - 级别：P2  
    位置：src/ui/select-sheet.tsx:21  
    现象：SelectSheet 组件在 value 不存在于 options 中时，直接显示 value 字符串（如已删除账户的 ID）而非“请选择”，可能误导用户以为账户仍有效。  
    复现要点：记账页选择账户 A，然后删除账户 A，再次打开记账页（资产列表未刷新）转出账户选择器仍显示 A 的 ID。  
    修复建议：检测 current 不存在时显示“请选择”占位，并在 onChange 中重置相关 state。
