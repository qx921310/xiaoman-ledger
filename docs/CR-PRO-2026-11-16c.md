  1. **P0** `src/features/bills.tsx:355-364` 转运行  
     现象：非选择模式下父行 `onClick` 设为编辑转账，行内“编辑/删除”按钮点击后会事件冒泡到父行，导致点“删除”时还会打开编辑转账弹窗，状态错乱。  
     复现要点：打开账单列表 → 点击一笔转账的“删除”按钮 → 观察到同时弹出编辑转账。  
     修复建议：在 `ledger-actions` 内按钮 `onClick` 加 `e.stopPropagation()`，或父行 `onClick` 判断 `if (e.target !== e.currentTarget) return`。

  2. **P0** `src/features/bills.tsx:378-391` 账单行  
     现象：父行 `onClick` 改为 `() => setDetail(b)`，行内“明细/编辑/拆分/复制/删除”按钮均未阻止冒泡。点击“删除”会额外打开该账单明细，删除后明细引用已不存在对象，可能渲染异常或误导用户。  
     复现要点：在账单列表点任一账单的“删除”按钮，观察是否同时打开明细。  
     修复建议：同 P0-1，在按钮层加 `e.stopPropagation()`，或父行只响应自身点击。

  3. **P1** `src/store.ts:deleteAsset 函数`  
     现象：`deleteAsset` 没有调用 `bookWritable`，只读账本资产仍可被删除并产生同步墓碑。与本次改动中 `updateAsset` 新增权限检查不一致。  
     复现要点：在含只读账本的环境下，通过命令层或 UI 删除归属于只读账本的资产，可成功删除并进入待同步队列。  
     修复建议：在 `deleteAsset` 内先定位资产并调用 `bookWritable(asset.bookId ?? s.currentBookId, s.accountBooks)`，不可写时返回 `{}`。

  4. **P1/待确认** `src/store.ts:updateAsset 函数`  
     现象：权限判断采用 `asset.bookId ?? s.currentBookId`。若资产缺少 `bookId`（旧数据/种子资产），且当前账本与资产实际账本不同，可能误改只读账本资产（绕过），或误拒绝可写资产。  
     复现要点：构造一个没有 `bookId` 但应属于只读账本的资产，切到可写账本后编辑保存，可能成功修改该只读资产。  
     修复建议：对 `bookId` 缺失的资产，不要 fallback 到 `currentBookId`；应禁止编辑或要求显式归属后再操作。待确认需结合资产历史数据结构。

  5. **P2/待确认** `src/features/assets.tsx` 新增 `account` 子页  
     现象：关闭账户页只执行 `setScreen('assets')` 未清 `historyAsset`；同时使用 `history.pushState` 写入状态但没有 `popstate` 监听，系统返回键可能造成页面与历史栈不同步。与金额守恒无直接关系。  
     复现要点：进入资产账户页 → 用系统返回键返回，可能回到错误页面或残留 `historyAsset`。  
     修复建议：关闭账户页时同时 `setHistoryAsset(null)`，并考虑监听/清理 `popstate`。

  6. **P2** `src/features/bills.tsx` 配合 `home.tsx:simpleView` 固定为 `true`  
     现象：`simpleView` 默认 true 后 `ledger-actions` 与“选择”栏均不渲染，列表页失去删除、编辑、拆分、复制、选择等操作入口。若是有意改为仅查看，可忽略；否则影响可操作性。  
     复现要点：首页账单列表不再显示账单操作按钮，点击行仅打开明细代替编辑。  
     修复建议：确认产品意图；若需要列表操作，调整 `simpleView` 默认值或提供替代入口。
