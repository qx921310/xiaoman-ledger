# 同账号多设备使用：检查报告（2026-11-12）

## 范围与结论

家庭财务空间暂时搁置。本报告针对两人使用同一登录账号在不同设备共同记账。检查基线为本地提交 `2c18f21`；隔离服务器使用临时 SQLite、虚拟账号和虚拟记录。未操作生产账本，没有进行真实 iPhone、两台设备或生产版本的端到端验收；生产站点只读检查返回 200，不证明部署版本与本地一致。

**能同时登录，但不能认定具备可靠的两人共同记账体验。** 手工依次同步可降低风险，不是完整的并发和数据安全保证。

## 证据与问题

1. **独立会话可并存（隔离服务实测）**：注册后用相同账号再次登录，两个 cookie 不同、指向同一用户；退出第一个会话后第二个仍能访问。服务端 `sessions` 独立保存令牌，默认 30 天。两人共享同一身份，无法可靠区分谁操作，双方拥有该账号全部数据。
2. **缺少持续自动同步（代码检查）**：`src/App.tsx:25-50` 初始化时同步一次；`src/features/settings.tsx:138` 提供手动同步。未找到记账后自动同步、轮询、网络恢复触发或前台恢复触发。两人长期打开页面会看到旧数据；自动同步失败仅写控制台，没有持续可见的失败提醒。
3. **并发编辑会丢失一方内容（隔离服务实测）**：两会话提交同一条账单、相同版本时间、不同备注，服务端两次都接受，最终只保留后一次；没有冲突提示。`server/server.mjs:573` 同时间允许覆盖，`src/domain/sync-merge.ts:150` 客户端只接受严格较新的版本，同时间还可能产生客户端与服务端不一致。设备时钟偏差也会影响先后判定；当前没有保留双方版本的冲突解决机制。
4. **非账单对象可能同 ID 覆盖（代码 + 服务端边界实测）**：普通账单以 UUID 创建（`src/identity.ts:2`），但 `src/store.ts:716` 转账 ID 用秒级时间戳并只检查本机，账户 ID 用毫秒时间戳（`src/store.ts:811`），退款等也使用本地时间戳。两设备同秒离线创建不同转账可能同 ID。隔离服务用同账号、相同 ID 和时间的两条不同账户模拟碰撞，两次推送均被接受，云端仅保留后一条。此实测验证服务端碰撞行为；转账端到端碰撞影响仍待完整复验。
5. **清空后旧数据复活（隔离服务实测）**：设备 A 清空账本后，设备 B 重放原有旧账单，服务端接受且旧账单重新出现。`server/server.mjs:509` 直接删除记录，没有阻止离线设备旧数据重推的代次屏障。界面另有本机“清空数据”，其语义也不同；不应依靠它清空多设备的云端数据。
6. **离线重开不可依赖（代码检查）**：`src/App.tsx:35` 启动先执行 `auth.me()`，而 `src/auth.ts:47-54` 网络失败返回未登录；未验证 iOS 浏览器的缓存、休眠和重新打开全流程。已打开页面断网后的本地输入与重连不等于可在断网状态下重新进入应用。
7. **余额有设计基础但需要双设备对账**：`src/balances.ts` 由期初与流水推导余额，账单 UUID 对独立新增有利；`src/sync.ts:54-55` 不上传余额缓存。但同步缺失、流水碰撞、版本覆盖仍会导致两端余额不一致。退款、报销、跨币种、关联删除、周期记账和批量导入均未完成双设备验收。
8. **备份和多标签**：本地数据使用账号键保存整个状态（`src/auth.ts:64-70`），未找到多标签状态协调机制；同浏览器多个标签同时修改具有本地持久化相互覆盖风险，需专项复现。JSON 恢复页面已提醒只替换当前设备，云端及其他设备同步后可能重新出现，不能把单设备恢复当成全账号回滚。

## 建议处理顺序

- **P0 防丢账**：各类独立业务记录使用稳定、全局唯一身份（包括转账、退款等）并保留旧 ID 的可追溯迁移；服务端按身份幂等。引入基于服务端版本的并发编辑／删除冲突检测，保留草稿和可恢复版本；清空改为有代次或墓碑的可验证协议。先做重放、乱序、重复、同秒、相等时间和设备时钟偏差测试。
- **P1 同步体验**：本地写入后防抖同步、重新联网和回到前台时同步，适当周期拉取；避免并发请求乱序，失败重试并明确显示待同步、最后成功时间及冲突。保证先后同步不会覆盖本地未提交修改；iOS 后台定时器不可靠，需真机验证。
- **P1 离线和账号安全**：明确会话过期和断网重开策略；提供设备会话查看和撤销、明确同账号无操作者身份区分。不要把自动本地登录设计成绕过服务端权限。
- **P1 双设备验收**：虚拟数据覆盖 A/B 同时登录和各自登出、新增账单、并发转账、不同步与重连、同账单冲突、退款、跨币种、周期、清空、账户余额、备份恢复、重新登录及两人 iPhone 实机。需要记录各设备步骤、同步状态、云端与账户流水结果。

## 临时使用建议（风险缓解，不是修复）

如必须试用：两人交替记账，操作前和操作后分别手动同步并确认成功，另一台拉取后再操作；避免同时编辑同一记录、避免离线并发转账和清空／批量恢复；定期导出 JSON 备份并确认保存成功。切记一方长期后台或离线时仍可能不一致；重要真实数据不应仅依赖当前多设备同步。

## 测试结果

- 本地 `npm run check`：通过（typecheck、测试、图标、视觉令牌、对比度、lint、build）。
- 隔离服务器虚拟账号：双会话并存／单端退出通过；同版本冲突覆盖、模拟同 ID 覆盖、清空后旧记录复活均已复现。
- 未测：两台真实设备、iOS 休眠及断网重开、完整双端账务链、生产服务端版本、真实用户数据。
