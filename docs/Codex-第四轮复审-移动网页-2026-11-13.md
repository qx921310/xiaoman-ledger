# 第四轮复审：移动网页（2026-11-13）

基准 `d90f460`，对照上轮 `24ece90`。重点检查前三个修复提交及其关联的记账、账户、模板、借贷、同步。Web 是目标平台；没有把 Android 原生能力缺失视为缺陷。本次使用本机隔离数据，不操作线上或 staging，没有 iOS 真机或双浏览器端到端验收。

结论：**本轮尚不能验收通过**。定存资金缺少流水、只读转账绕过及手续费错账本影响资金或数据归属；退款展示不符合用户已经确认的口径。以下复现均基于该提交的实际代码。

## P1

### 1. 定存直接改写期初余额，没有资金流水

`src/store.ts:525`、`:536` 和 `:558` 在新增及删除定存时直接加减 `openingBalance`。`src/domain/account-history.ts:31` 没有相应定存流水。

隔离 store 实测：初始账户 1000，新增 500 元定存并勾选累加，账户余额与期初均为 1500，账户流水 0 条。方向与文案一致，但用户无法知道额外 500 的来源；这也违背已经确定的“余额 = 期初余额 + 流水”原则。两设备离线各创建定存还会分别修改同一账户记录，账户更新与各自定存记录属于不同同步实体，冲突处理不能保证其作为一个资金操作原子完成；本轮未做双设备端到端复现，不把后者描述为已实测丢失。

参考方案：明确“累加”的业务含义，将其表示为具有稳定 ID、关联定存和账户的可同步余额变动记录；创建、删除时依选择生成或保留可追溯冲正记录，别修改期初。针对并发、冲突、同步顺序、清空、备份恢复及两种删除选择验证余额和明细闭环。

### 2. 只读账本仍能通过转账模板写入本地资金记录

`src/store.ts:717` 先执行转账模板并返回，`:730` 才检查 `silent`。隔离 store 实测：只读账本、账户 1500 和 0，应用 10 元转账模板返回 `true`，本地生成一笔转账，余额变成 1490 和 10。服务端是否拒绝不改变本地已发生的错误。

参考方案：转账在公共业务命令层检查目标账本权限、账户和共享约束，再统一供页面及模板调用；拒绝时不得更改任何状态。`tests/fix-regressions.test.ts:217` 的测试只覆盖普通账单模板，不覆盖转账模板；应补两个入口、在线/离线及手续费分支。

### 3. 跨账本转账模板的手续费落入当前账本

`src/store.ts:725` 将模板账本传给 `addTransfer`，但 `:966` 生成手续费账单时没有传 `patch.bookId`，于是 `addBill` 回退至当前账本。隔离实测：模板属于账本 1、当前选中账本 2，转账记到账本 1，2 元手续费记到账本 2。若当前账本只读，手续费校验还可能抛错，而模板目标账本本身可写。

参考方案：所有关联记录继承被确认的目标账本；转账和手续费应先整体校验再一次性提交，并验证删除、同步、账本统计及失败回滚。

### 4. 移动端债务页无法输入对方或选择借贷类型

`src/features/add-bill.tsx:228` 移动端已显示“债务”标签，但 `:238` 只区分转账和其他模式，债务时仍显示普通分类；输入对方及类型的控件仅在移动端提前返回之后的桌面分支 `:437`。保存逻辑 `:131` 必须有 `counterparty`，因此手机切换债务后无法填写必填项，点击完成只会提示“请选择债务”。这是代码路径核对，未做真机操作。

另外，桌面分支的“收款/还款”直接调用 `addLend`，不提供父借贷 ID；实际 store 隔离实测先借出 50，再按此方式收款 20，收款记录无父 ID，原借出仍显示未收 50。参考 `src/lend.ts` 的计算，应该让用户选择已有借贷并使用 `repayLend` 等具有关联与剩余额度校验的路径；新增借入/借出则分别校验账户、账本权限、时间和币种。两端均需完整交互测试。

## P2

### 5. 全额退款账单显示原支出，不符合用户确认的口径

`src/features/bills.tsx:374` 和 `:503` 改成展示 `cost` 原额。用户已明确要求“3 元账单退款 3 元后，显示支出 0，标记退款 3 元”；当前显示支出 3 和已退 3，与该要求及收支统计净额不一致。应显示退款后的净支出并标注退款，若需要保留原价可在详情另列，不改变退款到账流水。

### 6. 汇率缓存命中仍额外等待外网备用源

`server/server.mjs:888` 对非 CNY 的所有请求都等待备用源，即使缓存中已有对应本位币价格；`:882` 的请求未设置显式超时。备用源缓慢会拖住原本可由缓存完成的汇率请求。建议仅在缓存缺少有效基准时请求备用源，设置超时和有限缓存，使用固定 fixture 测试主源、备用源及缺失基准。当前 `tests/rates.test.mjs` 仍依赖外网，未替代这些确定性测试。
