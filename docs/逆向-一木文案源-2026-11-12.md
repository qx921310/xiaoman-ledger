# 一木 APP 文案源（DEX 提取）

## 为什么会有这份文档

一木的界面文案不在 `resources/res/values*/strings.xml`（反编译后为空），而是**编译进了 DEX 字符串池**。
直接解析 `resources.arsc` 也拿不到（字符串资源表在 arsc 的全局池里，但 androguard 当前版本 API 不匹配）。

**可行办法**：扫描 `classes*.dex` 中的 MUTF-8 中文序列。

```python
import re, zipfile
z = zipfile.ZipFile('yimu.apk')
pat = re.compile(rb'(?:[\xe4-\xe9][\x80-\xbf]{2}){2,}')
hits = set()
for n in [x for x in z.namelist() if x.startswith('classes') and x.endswith('.dex')]:
    for m in pat.finditer(z.read(n)):
        try: s = m.group().decode('utf-8')
        except Exception: continue
        if re.search(r'[\u4e00-\u9fff]', s): hits.add(s)
```

结果：**13245 条中文字符串**，落盘为 `research/yimubill/dex-zh.txt`（本地，未入库）。

## 对当前实现的结论

1. **一木有「全局默认账户 / 自动记账默认账户」这类设置**，不是简单的「自动建一个现金」。
   我们的兜底实现（账户为空时建「现金」）**只解决了阻断，不等于复刻**。
   要真正对齐，需要做「默认账户」设置项：指定一个账户作为记账默认选中。

2. 一木的账户类型文案是「现金 / 储蓄卡 / 信用卡 / 支付宝 / 微信余额 / 余额宝类」，
   不是我们现在的「资金账户 / 充值账户」这种抽象分类。**类型名需要按这份清单改**。

3. 新建账本时一木是否自动建账户集合，**仍未确认**（文案里没有直接的「新账本创建账户」提示）。
   需要真机跑一遍新建账本才能确定。

### 结论要谨慎看

「找不到」**不等于**「一木没有这个说法」，原因有三种：

1. 我们自己的功能（云同步、迁移、账单组、附件 30 天等），一木没有对应文案 —— 正常
2. 一木是**动态拼接**（如「${账户} 余额」），池里只有片段 —— 需要按片段比对
3. 真的用了不同措辞 —— 这才是要改的
