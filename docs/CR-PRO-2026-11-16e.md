1. **P1 | src/store.ts:1871-1874**  
   **现象**：`updateAsset` 只读校验使用 `asset.bookId ?? s.currentBookId`，而不是状态中既有账户的 `a.bookId`；随后 `{ ...asset }` 直接覆盖原账户，允许把只读账本账户改到可写账本或直接改余额/期初。  
   **复现要点**：存在 `silent` 账本 S 和可写账本 W，资产 A 属于 S；调用 `updateAsset({ ...A, bookId: W, assetNumber: 99999 })` 或省略 `bookId` 且 `currentBookId` 为 W，校验通过，A 被更新并可能迁出 S。  
   **修复建议**：先 `const old = s.assets.find(a => a.assetId === asset.assetId)`；无 `old` 直接失败；用 `old.bookId ?? s.currentBookId` 做 `bookWritable`；禁止通过 updateAsset 修改 `bookId`；让命令返回 boolean 供 UI 判断。

2. **P2 | src/store.ts:1447-1455**  
   **现象**：`addAsset` 权限校验使用 `patch.bookId ?? s.currentBookId`，但实际落盘资产来自 `...patch`，未设置 `bookId` 默认值；当调用方省略 `bookId` 时，校验与资产归属不一致，可能导致新资产没有账本作用域或同步错乱。  
   **复现要点**：`currentBookId` 为可写账本时调用 `addAsset({ assetName: 'x' })`，权限按当前账本校验，但新增资产 `bookId` 为 `undefined`。  
   **修复建议**：计算 `const bookId = patch.bookId ?? (s.currentBookId === 0 ? undefined : s.currentBookId)`，校验和写入都用该值。

3. **P2 | src/store.ts:1436-1442**  
   **现象**：`deleteAsset` 写墓碑时只有 `kind/id/ownerId/updatedAt`，没有 `bookId`；仓库内其他业务墓碑普遍带 `bookId`。服务端若按 `bookId` 作用域合并，删除可能无法正确传播或错误影响同 ID 资产。  
   **复现要点**：删除某账本资产后同步，观察云端该资产是否按账本维度被删除/复活。  
   **修复建议**：墓碑补充 `bookId: target.bookId`，并直接使用 `target.userId`；若服务端不要求，请标注待确认。

4. **P2 | src/features/assets.tsx:337-339**  
   **现象**：账户子页新增“编辑”按钮未按 `readOnly`/命令层权限禁用；只读账本资产仍可打开编辑器，保存被 `updateAsset` 静默拒绝后 UI 仍提示“账户已更新”，权限拒绝被掩盖。  
   **复现要点**：打开只读账本资产账户页，点编辑并保存，提示成功但余额未变。  
   **修复建议**：为编辑按钮加 `disabled={readOnly}` 或根据 `updateAsset` 返回值提示。

5. **P2 | src/features/stats.tsx:184-187**

   **复现要点**：有信用卡负余额时查看“资产汇总”，负债不显示。
