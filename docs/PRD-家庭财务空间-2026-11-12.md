# 小满记账：家庭财务空间 PRD

> 版本：v0.1 讨论稿｜2026-11-12｜状态：已搁置（2026-11-12），暂不开发或迁移；当前优先评估同账号多设备
>
> 目标读者：产品负责人、设计、开发与验收。本文以家庭共同管理财务为主线；“空间”“家庭空间”等名称均为暂定。

## 1. 一句话定义

家庭空间让 2～6 位成员使用各自的账号，共同管理空间内的账本、账户、流水和统计。每位成员仍拥有独立的个人空间；加入家庭空间不会自动公开或搬迁原有个人数据。

示例：你和伴侣加入「我们的小家」，家庭工资、餐费、银行卡余额在家庭空间里共同维护。你自己的一本私人账本和未加入家庭空间的银行卡，另一位成员看不到。

## 2. 背景与已确认方向

### 2.1 要解决的问题

现在的多人能力围绕“共享一个账本”设计，账户是否共享和账本绑定在一起。添加私有账户到多人账本会被拦截，用户很难理解“为何为了记一笔账要共享资产”。对希望共同查看家庭账户和家庭财务的夫妻来说，它也没有把“家庭拥有一套财务数据”表达清楚。

用户已确认：

1. 家庭共同管理是一等场景；短期旅行、AA 等属于可扩展场景，不作为首版主线。
2. 多人各自登录，共同维护家庭空间内的一套账本和资产，而不是多人共用一个登录账号。
3. 家庭空间之外的个人空间独立，加入时不自动共享个人历史账本或资产。
4. 产品能力可以复用空间和成员体系，未来支持只共享账本的团体，但不可让旅行朋友自动获得家庭其他数据的权限。
5. 当前小满多人账本设计需要重新评估；不得把现有账本直接视作已满足本 PRD。

## 3. 目标、范围与非目标

### 3.1 首版目标

- 成员可以创建、加入和切换家庭空间，明确看到当前所在空间。
- 家庭成员可共同新增、查看、修改授权范围内的家庭账单和家庭账户。
- 家庭资产余额按家庭流水推导，多设备同步后结果一致；个人资产不进入家庭总资产。
- 成员加入、退出、移除后，服务端权限、同步与界面表现一致。
- iPhone 移动网页和桌面网页使用同一服务端规则；为后续微信小程序预留接口，不以小程序上线作为首版完成条件。

### 3.2 首版不承诺

- 独立的旅行空间、账本级外部邀请、按账单或按字段逐项授权。
- 实际银行账户连接、代扣、转账或支付；小满只是记录财务信息。
- 自动同步个人资产到家庭或将历史个人账单批量共享。
- 复杂审批、聊天、多人同时编辑同一字段、家庭内账户按人细分权限。
- 现有全部高级功能（股票、贷款、分期、周期、AA、OCR、导入等）未经权限和余额验收就直接宣称支持家庭空间；每项应显式标识支持或暂不可用，不能静默写入错误空间。

## 4. 名词与数据边界

| 名词 | 定义 | 所属范围 |
|---|---|---|
| 登录账号 | 一个真实使用者的登录身份，可在多设备使用 | 用户 |
| 个人空间 | 用户个人财务数据范围 | 仅本人 |
| 家庭空间 | 多成员共同管理的一套财务数据 | 当前有效成员 |
| 账本 | 账单的组织单位，一个空间可包含多个账本 | 仅所属空间 |
| 账户／资产 | 现金、银行卡、信用卡等；保存期初余额、币种等 | 仅所属空间 |
| 流水 | 影响账户余额的账单、转账、退款、报销等资金变动 | 跟随所属空间及账户 |
| 成员与角色 | 用户与空间的授权关系 | 某个家庭空间 |

**空间是首版最高数据隔离边界。** 账本和账户不是一对一绑定：家庭空间中，一张家庭银行卡可用于家庭日常账本及装修账本；个人银行卡仍属于个人空间。家庭空间总资产按家庭空间账户计算，不因为切换家庭空间内的账本而改变。

### 4.1 首版明确的记账限制及待定事项

为保证“共同管理同一套账户”和余额口径可验证，**首版建议家庭账单只直接选择家庭空间账户；个人账单只选择个人空间账户**。账户不需要绑定某一本账本，但暂不能跨空间直接引用。

这是一项需要产品确认的取舍，不等于“账户必须绑定账本”。真实家庭里可能有人用自己的私人银行卡垫付家庭餐费；若需要这类场景，未来应明确设计“个人垫付／家庭欠款或结算”，而不是把个人卡和家庭卡合并或偷偷公开余额。首版是否把“个人垫付家庭支出”列为阻塞需求，见第 13 节。

## 5. 用户与权限（建议稿）

| 操作 | 创建者 | 管理员 | 普通成员 |
|---|---:|---:|---:|
| 查看家庭空间内账本、账户、流水、预算 | 是 | 是 | 是 |
| 新增家庭账单、退款、转账 | 是 | 是 | 是 |
| 修改／删除家庭账单 | 是 | 是 | 是，默认可修改任一家庭账单（留操作记录） |
| 创建及维护家庭账户 | 是 | 是 | 是，修改期初余额需二次确认与记录 |
| 邀请成员 | 是 | 是 | 否 |
| 移除普通成员 | 是 | 是 | 否 |
| 任免管理员、转让创建者 | 是 | 否 | 否 |
| 删除家庭空间 | 是 | 否 | 否 |
| 查看其他成员个人空间 | 否 | 否 | 否 |

说明：共同维护意味着普通成员不默认只读，也不限于只修改自己记录；但这与现有共享账本文档默认“只能改自己”不同，**属于待确认的建议**。如更希望防误操作，可将删除他人账单改为仅管理员允许。创建者、管理员、普通成员都不因角色获得其他人的个人数据。

每次写操作记录操作者和时间；账单同时保留原记账人。操作记录不应影响余额，显示“谁创建、谁最后修改”；审计记录保留范围和恢复能力按后续设计明确。

## 6. 主要用户流程

### 6.1 创建家庭空间

1. 个人空间中的入口选择「创建家庭空间」，输入空间名称。
2. 页面说明：空间内账本、账户余额及流水对成员可见；个人空间不自动共享。
3. 创建成功后生成一个空的家庭空间、默认家庭账本；创建者自动加入。
4. 进入空间空态，引导添加家庭账户或邀请成员；不能凭空复制个人余额。
5. 离线不能创建服务端家庭或邀请时，明确提示联网，不假装已成功。

### 6.2 邀请和加入

1. 创建者或管理员生成有效期内、可撤销的邀请码／链接；具体有效期可沿用现有 24 小时作为建议，待确认。
2. 被邀请人登录自己的账号后，先看到空间名称、邀请人、成员数和共享范围：**家庭空间的账本、账户余额和流水将对家庭成员可见；自己的个人空间不自动共享**。
3. 主动确认加入；不得静默加入或把私人数据自动迁入。
4. 单空间成员上限 6 人，包含创建者；重复加入、过期、撤销、满员均显示明确结果。
5. 验证成员已被移除、空间删除、邀请码被撤销等情况下的竞态；加入以服务端结果为准。

### 6.3 添加家庭账户与记账

1. 用户先切到家庭空间，再添加「家庭招商银行」，输入币种、期初余额和其他需要的账户信息；提示家庭成员可看到账户及余额。
2. 在家庭日常账本记一笔 30 元午餐，选择该家庭账户。账单显示记账人、账户、时间、金额。
3. 家庭空间内该账户余额减少 30 元；其他成员同步后，在家庭资产页和账单页看到一致结果。
4. 同一家庭账户可以被同空间内其他账本引用，余额基于同空间所有关联流水；家庭资产总额不能因切换账本发生变化。
5. 在个人空间，不显示家庭空间账户；家庭成员不能从家庭页面访问你的个人账户。

### 6.4 修改、删除、退款与转账

- 修改账单金额或账户时，以更新后的真实流水重新推导涉及账户余额，不能同时保留旧扣款与新扣款。
- 删除账单时同步删除状态并回滚影响；若存在退款、报销等关联，必须先明确级联策略并提示，不能留下悬空记录。具体是否阻止删除或联动删除待产品确认，首版未定前不得上线该路径。
- 支出 30 元后退款 10 元：账单按现有产品口径显示净支出 20 元，同时退款作为资金流水回到指定家庭账户；若全退，净支出为 0，仍保留完整资金流水。
- 家庭账户 A 转到家庭账户 B：A 扣款、B 加款；本金不计家庭收支；手续费按现有业务规则处理且不得重复计入。两边同属家庭空间。
- 外币需保存可复算的账户币金额与发生时汇率；汇率变动不追溯更改历史流水。无法确定历史金额时应待核对，不能猜测。

### 6.5 退出、移除与删除

- 普通成员退出或被移除后，服务端立即拒绝该成员读取和写入家庭空间；其此前创建的家庭账单和资金记录保留在家庭空间，保留记账人历史标识。
- 离线时被移除：本地可以提示“权限待确认”，重连后阻止上传并保留未同步内容供用户核对／导出；不得重新授权或静默丢弃。对已下载数据的清理策略及用户已自行复制的数据边界要明确，不能承诺撤回截图或已导出内容。
- 家庭空间删除或创建者退出：需要先制定转让、确认、恢复和成员通知的具体方案，首版默认先不开放直接解散／创建者退出，避免误删真实资产数据；不是永久产品限制。
- 成员退出、移除和空间删除的保留期限、导出范围、恢复流程须在实现前形成可验收规则。

## 7. 页面与交互原则

- 顶部或主要导航始终明确标识「个人空间／家庭空间名称」，切换前后保留可辨识状态；禁止仅用账本名暗示空间。
- 资产页标题明确「个人资产」或「家庭资产」。家庭资产页展示成员共同维护的资产，不混入个人资产；家庭成员拥有授权后可看到家庭余额。
- 家庭账单显示记账人，编辑后可查看最后修改人。账户栏使用家庭账户名称，不暴露其他成员的个人账户细节。
- 邀请确认和新建家庭账户时，用简短文案说明共享的账本与余额；提供清楚的取消入口。
- 空间切换时检查未保存的表单，提示用户保留草稿或放弃，不得误写入另一个空间。
- Web 和未来小程序的页面可不同，但共享范围、金额规则、权限和服务端校验一致。移动端优先，兼顾桌面网页。

## 8. 账务与一致性要求

1. **单一归属**：每条账单、账户、转账、退款等记录只能归属一个空间；账本与账户的空间必须匹配，服务端负责校验，不信任前端传入的空间或成员身份。
2. **流水为权威**：余额 = 账户期初余额 + 同空间该账户全部有效资金流水。余额是派生结果；同一账户在不同账本产生的流水均计入。
3. **金额口径**：以最小货币单位进行运算或采用等价精确方案；币种、汇率与退款方向需有清晰快照，不靠浮点反复累加。
4. **离线优先**：允许已授权成员离线记账，使用不会因为同秒或多设备而碰撞的稳定身份；离线记录标记待同步。当前是否具备足够的数据和权限缓存需在技术设计中验证。
5. **冲突不静默丢账**：不同成员不同账单必须都保留；同一账单被离线并发修改时应提示冲突并保留可恢复的双方版本，具体交互及合并策略待技术方案明确。删除与编辑冲突同理，不以客户端时间简单覆盖为最终方案。
6. **幂等**：重复推送、重试、乱序或断线重连不重复创建流水；同一业务操作相关记录需要具备事务性或可恢复的一致性机制。
7. **周期账单**：多设备同一期不能重复计入余额；期号及冲突必须有服务端约束和客户端回执，冲突账单不得静默丢失。
8. **校验边界**：服务端分别校验空间成员、权限、账户归属、账本归属和引用关系；成员移除立即影响服务端读取与写入权限。UI 隐藏不是授权。
9. **备份恢复**：必须定义个人／家庭空间导出范围、成员变更后的可恢复数据及导入防重复。未经同空间权限校验，不能用备份把家庭数据恢复到他人空间。

## 9. 现状差距与迁移

当前实现以账本及其成员作为主要共享单位；部分账户带 `bookId`，账户同步移除计算余额字段但仍可能同步期初余额；资产列表会显示共享到账本的账户。现有服务端也会拦截多人账本引用私有账户。以上与目标模型存在差异；具体代码以开发时固定提交重新核查。

迁移原则：

1. 先在预发对实际版本做只读盘点：账本、成员、账户、流水、退款及转账的现有归属和引用关系。
2. 在允许操作前创建可验证备份；迁移脚本支持预演、统计、幂等、失败中止与恢复。保留原始标识映射和审计报告。
3. 仅凭能证明的归属自动迁移；原共享账户究竟应成为家庭账户还是个人账户，不能由系统猜测，交由相关成员确认。多账本引用、缺失 owner、冲突或孤儿记录列入待核对。
4. 个人数据不会因启用家庭空间而默认公开；迁移中须有预览和共享范围确认。旧客户端在新权限模型上线后可能绕过客户端限制或错误同步，服务端必须拒绝不兼容写入或提供受控兼容策略，不能只更新新版前端。
5. 迁移后核对每账户期初、各类流水、余额、账单数和成员权限；有差异时暂停切换，保留证据与可执行的回退方案。不要用一次性余额调整掩盖缺失流水。
6. 方案批准前不对生产数据迁移。预发与生产数据隔离，真实账单不用于试错。

## 11. 验收场景

| 编号 | 场景 | 必须结果 |
|---|---|---|
| AC-01 | A 创建家庭并邀请 B | B 见到共享范围，经确认加入；A、B 登录账号各自独立 |
| AC-02 | A 有私人卡和私人账本 | B 无法通过页面、接口、同步、导出、附件或关联记录看到 A 私人资产余额和流水 |
| AC-03 | 家庭卡期初 100，A 在家庭日常账本支出 30 | A、B 同步后家庭卡均为 70；A 私人卡与余额不变 |

## 13. 需要产品负责人审阅的决策

以下均为**待定**，不应由开发静默决定：

1. **个人卡垫付家庭消费是否为首版必需？** 建议先选择：A 首版仅家庭账户；B 首版支持个人垫付，但需明确“家庭支出／个人余额／家庭欠款”三方关系及结算。
2. **普通成员能否修改／删除他人家庭账单和维护家庭账户？** 本稿建议共同维护并保留操作记录；也可限制删除他人记录或敏感账户操作。
3. **家庭收入与个人收入如何记录？** 是由用户决定记进家庭账本，还是需要“个人工资部分转入家庭”的专门流程？不能将家庭账户与个人账户转账当普通同空间转账处理。
4. **首版范围：预算、周期账单、导入、AA 哪些必须支持？** 建议先保证家庭账单、账户、退款、转账、统计闭环，其余若未完成应隐藏或明确不可用。
5. **退出与解散**：创建者转让、空间解散、导出及恢复期限如何设定？本稿建议首版先不开放直接解散或创建者退出。
6. **历史共享账本如何处理？** 保持原样一段时间、按家庭确认迁移，还是提供单独导入流程？现有成员和账户是否应逐项确认？
7. **命名与数量**：“家庭空间”是否采用此名？每个账号是否可加入多个家庭空间？首版上限除每空间 6 人以外尚未确定。
8. **成员隐私与记账人展示**：是否统一展示昵称及账户名？离开成员使用什么历史显示名？不显示个人资料与历史账单保留如何兼顾？
9. **冲突处理**：同一账单多端离线修改，优先人工核对还是保留两个待确认版本？删除和修改冲突怎样恢复？
