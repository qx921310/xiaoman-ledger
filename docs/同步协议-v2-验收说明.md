# 同步协议 v2：实现与验收边界

- 服务端记录有单调递增版本；客户端携带基版本，版本不一致时拒绝覆盖并保留本地草稿。
- 清空账本在事务内写墓碑并增加账本代次；旧代次操作不能写入。账本流水缺少账本身份时拒绝写入。
- 操作先保存在账号隔离的本地队列，服务端以操作 ID 去重。批次发生冲突时整体回滚，避免关联操作只写入一部分。
- 首次升级时，旧账本中仅存在于本机的流水无法证明产生时间，会停留在待核对状态。比较两端内容后可显式选择本机版本，并在本机备份两份快照。处理后若其他冲突未解决，整批提交仍会等待。
- 会话切换中止旧请求并校验会话代次；支持 Web Locks 的浏览器会串行化同源标签页的同步队列。没有 Web Locks 的浏览器仍使用原有标签协调机制，不能视为已验证的跨标签队列互斥。
- 已用隔离服务器、虚构账号和两份浏览器存储验证离线并发编辑：分别修改为 35 和 40 元，冲突界面显示两份记录，选择本机版本后另一端收到 40 元。另验证清空前离线新增在重开后仍留在本机并提示旧代次；清空使用隔离服务接口触发，浏览器清空确认框未完成自动化。测试发现清空误删账户和账本信息，已修正并由服务端回归测试覆盖，但修正后的清空流程尚未再次双浏览器验收。
- `tests/sync-v2-integration.test.mjs` 使用真实临时服务端及两个独立客户端状态，验证修正后清空不会删除账户与账本信息，旧草稿仍留在本地，云端没有旧草稿。该测试已加入 `npm run check`。
- 不支持旧客户端继续向已升级账号或账本推送；上线需确保服务端先于客户端升级，并安排备份、旧设备升级、灰度及回滚方案。未在生产数据上迁移或测试。
- 当前冲突界面支持显式使用本机版本；尚无直接选择云端版本的交互，JSON 恢复文件中的同步快照也没有自动恢复流程。保留记录供人工核对，不应将此轮视为生产验收完成。
