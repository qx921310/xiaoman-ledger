# ADR：同步身份与周期期号（架构立项）

状态：**待实施**　提出：Codex 第三/四轮验收　影响：离线记账可用性、跨设备一致性

## 1. 问题

当前"本地优先 + 客户端各自决策"导致同一业务事实被多台设备各做一遍：

| 现象 | 根因 |
|---|---|
| 同 ID 不同属主的记录要顺位改号，改号后引用不更新 | 客户端发明身份 |
| 周期账单多设备重复生成 | 期号由客户端按本地日期判断 |
| 墓碑重复拉取可能误删 | 墓碑身份 = 类型 + 原编号，缺属主/作用域 |
| 标签、预算删除跨设备不生效 | 无属主类型与有属主类型混用同一套匹配规则 |

补丁能收敛到"不丢数据"，但收敛不到"天然正确"。

## 2. 目标（不是"必须联网"）

**离线创建，服务端确认身份与期号。**

- 手工账单：设备生成全局唯一 ID（UUID），**离线可记**；服务端负责校验、存储、分配展示编号
- 周期账单：服务端按业务键做唯一约束与幂等写入
- 身份与期号是**服务端权威**，客户端只缓存结果

## 3. 设计

### 3.1 记录身份

```
identity = (scope, kind, business_id)
scope    = 'user:<userId>' | 'book:<bookId>'
```

| 类型 | scope | business_id |
|---|---|---|
| 账单 / 转账 / 借贷 / 退款 / 报销 / 周期 | book | 客户端 UUID |
| 资产 / 分类 / 标签 / 预算 | user | 业务 ID（预算为 `month:categoryId`） |

**所有**匹配（普通记录合并、墓碑删除、改号回填）使用同一套 identity，不再一处按属主、一处按编号。

### 3.2 周期期号

```
period_key = hash(bookId, cycleId, dueDate, timezone)
```

- 服务端对 `period_key` 建唯一索引
- 客户端离线时把候选账单标记 `pendingPeriod`
- 同步时服务端返回 `created | existing | conflict`
  - `created`：落下
  - `existing`：本地候选作废（墓碑本地化，不推送）
  - `conflict`：内容或关联不一致 → 保留两条并标记「待核对」

### 3.3 客户端职责

| 场景 | 行为 |
|---|---|
| 离线记账 | 正常写本地，标 `pending` |
| 联网同步 | 推送候选 → 接受服务端裁决 → 回写真实 ID / 期号 |
| 冲突 | 不自动合并：保留 + 提示核对 |
| 服务端不可用 | 继续本地可用，标记待同步 |

## 4. 迁移

1. **只读扫描**：找出身份冲突、重复周期账单、错账分类 → 输出报告
2. **备份**：迁移前导出 JSON
3. **按证据迁移**：只有能证明归属的才自动改；不能证明的标「待核对」交给用户
4. **不猜测**：绝不按"当前账本"或"当前时间"推断历史归属

## 5. 分阶段

| 阶段 | 内容 | 可独立上线 |
|---|---|---|
| A1 | 客户端集中身份比较逻辑；无法确定作用域的旧数据保守处理（不删、不合并） | ✅ |
| A2 | 拉取协议向后兼容扩展：墓碑与记录都返回 `bookId`/`ownerId` 作用域 | ✅ |
| A3 | 服务端周期期号唯一约束（`period_key`） | ✅ |
| B | 服务端记录身份表 + 幂等写入 | ✅ |
| C | 周期期号服务端唯一约束 | ✅ |
| D | 历史数据扫描与迁移工具 | ✅ |

## 5.1 为什么 A 不能"完全不动服务端"

Codex 指出：拉取接口目前不返回墓碑的 `bookId`，而删除记录的 payload 可能为空，
客户端无法总是还原 `book:<id>` 作用域。因此：

- **A1 只能保守处理**：无法判定作用域的旧数据一律不删、不自动合并
- **A2 必须扩展协议**：`/api/data/pull` 每条记录返回 `ownerId`（已有）+ `bookId`（墓碑也要有）
- 只有拿到完整作用域，A3 之后才能安全地用同一套身份做删除与合并

## 6. 验收标准

- 两台设备离线各记一笔同期周期账单 → 联网后**只有一条**，另一条标 `existing` 作废
- 同一墓碑重复拉取 N 次，结果恒定
- 标签/预算删除在另一设备生效
- 离线时记账、看统计、改账单全部可用
- 历史错账有扫描报告，无静默改写
