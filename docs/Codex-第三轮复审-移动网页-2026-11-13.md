# 第三轮复审：移动网页（2026-11-13）

基准：`24ece90`，对照上轮 `8846cde`；审计时业务工作区干净，仅已有未跟踪文档。范围为记账、定存、模板、同步、账户身份与新汇率接口；参考已有 APK 取证材料，不以 Android 原生能力是否具备为 Web 的通过标准。无生产、staging 或 iOS 真机操作。

**结论：仍不建议用于真实财务数据。** 之前的问题有修复，但本轮新增了汇率和定存资金方向错误、权限校验缺口，以及默认账户标识与功能冲突。

## P1

### 1. 非主源支持的本位币会收到错误汇率，且被当成功写入

`server/server.mjs:869` 的 `toBase` 在 `base` 对应价格不存在时，返回未经换算的人民币报价，但将 `base` 标记为请求币种。主源/兜底的 `wanted` 列表（`:878`）未包括 MYR、THB、TWD 等现有币种；`src/features/settings.tsx:1378` 将这些报价依请求的本位币写进本地汇率。

隔离真实服务端、模拟 CFETS 只返回 `USD/CNY=7`、`EUR/CNY=8`：请求 `base=MYR` 返回成功，结果却是 `base: MYR, USD: 7, CNY: 1`。7 实际是人民币报价，不是马币报价。用户刷新后用该值记账，支出、账户余额和统计可能均错误。

建议：若缺本位币的有效基准，应从可信来源补全或返回明确失败，不能带错币种标签成功；只有完整校验后原子更新汇率，缺少部分币种需明确提示。测试所有支持的本位币、部分主源结果、fallback、舍入与切换本位币；不依赖真实外网的固定样本测试。

### 2. “累加至账户余额”实际上扣减账户，隐藏资产造成净资产减少

`src/features/fixed-deposit.tsx:94` 的开关文案是“累加至账户余额”；`src/store.ts:513` 创建隐藏的虚拟账户，`:519` 把用户选择账户作为 `fromAssetId`。隔离 store 实测：账户 1000，定存 500 后选中账户变 500，虚拟账户变 500 且隐藏。与开关字面方向及此前按 APK 证据描述的“累加”相反；隐藏账户还不参与现有总资产显示。

用户选择删除定存、在确认框选择“不同时扣回”时，`:540` 保留转账，`:543` 仍删除虚拟账户。实测结果：原账户仍为 500、转账保留、转入账户已不存在，留下悬空流水。

建议：首先核实 APK 中所选账户的角色及勾选/取消语义，建立与用户文案一致的资金模型；保存与删除应是完整、可恢复的业务事务。覆盖本币/外币、两种删除选择、资产总额、流水、清空和备份恢复。上轮“流水为权威”的问题不能仅通过新建一条方向相反的转账视为解决。

### 3. 新现金账户为负数 ID，却被定存和转账模板当无效账户

`src/App.tsx` 的确定性现金 ID 为负数；`src/features/fixed-deposit.tsx:111` 和 `src/store.ts:508` 却要求关联账户 `> 0`，`src/store.ts:706` 的转账模板也要求两端 ID `> 0`。

隔离 store 实测：有效现金账户 `assetId=-123`、余额 1000，创建定存时请求累加 500，最终记录 `toAsset=false`、转账 0 条、余额不变。页面可勾选却在保存时静默取消。转账模板引用该默认现金账户也会被拒绝。

建议：区分明确的无账户哨兵与有效业务 ID，统一按账户是否存在校验，不以正负判断；覆盖默认现金的所有入口以及真实新增、删除与模板。注意不能把历史无账户 `-1` 当成真实账户。

### 4. 只读账本可通过转账模板创建本地流水

`src/store.ts:703` 的 transfer 模板分支先调用 `addTransfer` 并返回，`:711` 之后才检查目标账本是否 `silent`，因此检查对转账无效；该分支也没有确认账户仍然存在。

隔离实测：账本 role=`silent`、A 账户余额 100，执行 10 元转账模板返回 `true`，本地生成 1 条转账、A 余额变为 90。服务端后续可能拒绝，但本地已显示错误结果。

建议把身份、账本权限、账户存在与共享约束、金额、汇率、方向校验抽为统一业务命令，所有页面/模板/周期路径调用；测试线上与离线只读、账户删除、跨账本、同步拒绝和余额保持不变。

### 5. 旧记录认领属主没有校验账本与内容，底层合并可覆盖另一条记录

`src/domain/sync-merge.ts:134` 只因为本地同 ID 的 owner 为 0 就把云端 owner 写入，随后可能按新版本覆盖；没有核对两个 `bookId` 是否相同。隔离调用实际 `applyRemote`：本地旧愿望 ID=123、账本 A，云端另一属主同 ID、账本 B，合并后只剩 B 的记录。

当前 v2 runner 在某些场景会先按内容/版本阻止合并；以上是底层合并函数和直接 store 动作的确定复现，**尚未证明经完整 v2 同步链必然丢失**。但这是不安全的身份认领，不能以单条同属主测试认定历史记录已安全迁移。

建议：依据作用域、已验证身份及基线证明后认领；不同或未知身份保留为冲突，不能推断为同一记录。覆盖不同账本、同账本不同属主、内容相同/不同、墓碑及真实 v2 循环。

### 6. 标签 ID 可碰撞，已导致测试偶发失败

`src/store.ts:1529` 使用 `NOW() + Math.floor(Math.random() * 1000)`，没有检查本地占用；不同毫秒也可能因随机偏移相同。`npm run check` 在 `tests/balance.test.ts:648` 失败：预期子标签父名称“出差”，实际 `undefined`；单独重跑通过。

隔离环境将时间和随机值固定后，连续添加父子标签得到相同 ID 且存在两条；按 ID 查找会命中父记录。删除、编辑、同步也会受影响。建议采用不可碰撞的身份方案并兼容历史数字 ID；测试强制碰撞、快速连续创建、跨设备以及已有重复修复。

### 7. 现金种子测试没有覆盖实际 v2 并发，且 Windows 清理不稳定

`tests/concurrent-seed.test.mjs` 推送的 body 未设置 `protocolVersion: 2`、`operationId`、`baseVersion`，走旧协议；它只断言服务端一条，不能证明实际 v2 两端无待核对。隔离使用真实 `runVersionedSync` 和两份不同 `updateTime` 的同 ID 本地种子：云端 1 条，但后同步设备产生 1 条版本冲突。

此外第一次 `npm run test:seed` 以 Windows `EBUSY` 失败，因 finally 在 `child.kill()` 后未等子进程退出就递归删除 SQLite；复跑通过。建议使用真实 v2 客户端协议、两端本地状态及同步回执断言，在清理前等待子进程退出；处理自动种子等价并发时不能覆盖用户后来编辑的账户。

## P2 / 待确认

### 8. 语音和外币模板仍未形成一致记账流程

移动端新增了语音和模板入口，但语音回调用 `setRemark`（`src/features/add-bill.tsx:72`），没有经过智能分类的 `onRemarkChange`；模板只保存输入数字和账户，没有保存当前选择的记账币种，而执行时按账户币种解释金额（`src/store.ts:735` 左右）。例如以 CNY 账户记录 10 USD 并存模板，原币种信息不会被模板保存，后续难以恢复原折算语义。需定义模板保存的原币、本币、账户金额快照，以及语音后智能分类和用户手动覆盖的顺序。

### 9. PIN 冷启动有短暂先渲染业务内容的可能

新版已经在 user 就绪后重新设定作用域和锁定，但 `locked` 初始为 false，`src/App.tsx:26` 使用 `useEffect` 才设为 `hasPin()`；在 effect 执行前已可渲染 `Shell`。是否肉眼可见取决于渲染时序，未在 iOS 真机复现。建议在账号锁定状态确定前只渲染占位，避免先显示账目；旧无作用域 PIN 迁移也应单独确认。

### 10. 自动汇率测试依赖真实互联网和主源可用

`tests/rates.test.mjs` 不 mock 上游，强制断言 `source === 'cfets'`；当主源临时不可用但设计允许备用源成功、网络受限或外部数据变动时 `npm run check` 也会失败，且不能覆盖缺基准币、部分报价等情形。建议将确定性 fixture 纳入主闸门，外网探活单独运行。
