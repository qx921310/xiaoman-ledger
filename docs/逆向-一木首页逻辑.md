# 一木记账：首页业务逻辑（APK 反编译结论）

来源：`apk-src/sources/com/wangc/bill/Fragment/HomeFragment.java`（1846 行）、`activity/AddBillActivity.java`（2626 行）。

## 1. 首页 = 汇总 + 记账入口 + 最近账单

- 顶部三个汇总位：`monthIncomeLayout` / `monthPayLayout` / `monthBalanceLayout`（本月收入 / 本月支出 / 本月结余）
- 中间：快速记账入口（跳 `AddBillActivity`）
- 下方：**最近记账列表**，这是和记账页同屏展示的核心

## 2. 首屏秒开：先读缓存，再异步刷新

```java
// 渲染完成后立刻把结果写进缓存
g.t0("homeBillList");
g.d0("homeBillList", new Gson().toJson(T0(list)));
```

- 三个独立缓存键：`homeBillList`（普通账单）、`homeStockList`（股票）、`homeTransferList`（转账）
- 冷启动时先用缓存渲染，网络/数据库结果回来后再覆盖
- **三类数据分开缓存、分开刷新**，互不影响

## 3. 首页只留最近 50 条

```java
private static <T> List<T> T0(List<T> list) {
    return (list == null || list.size() <= 50) ? list : new ArrayList(list.subList(0, 50));
}
```

列表和缓存都截断到 50 条。首页不承担"全量浏览"的职责。

## 4. 分页按 30 天窗口，不是按条数

```java
public static final long f39839z = 2592000000L;   // 30 天（毫秒）

public void U0() {                 // "home loadMore"
    long jY = ...;                 // 当前列表最早时间
    C = jY;
    B = jY - f39839z;              // 再往前推 30 天
}
```

- 加载更多的粒度是**时间窗口 30 天**，而不是 `pageSize=20` 这种条数
- 原因：记账数据天然按时间聚集，按天切更符合用户"往下翻更早的账"的心智

## 5. 记账页保存后返回上一页

```java
setResult(-1);   // 三处调用
```

`AddBillActivity` 保存后 `setResult(-1)` 并结束，由首页接收结果后刷新列表。
→ **一木是"记完就回去看结果"，不是"记完留在原页继续记"。**

## 6. 与我们现状的差异

| 方面 | 一木 | 小满 |
|---|---|---|
| 首页 | 汇总 + 记账入口 + 最近账单同屏 | 只有记账表单，看不到最近记了什么 |
| 首屏 | 缓存优先，异步刷新 | 本地全量数据，天然快（但数据量大时全量 rehydrate 会卡） |
| 列表粒度 | 30 天窗口滚动加载 | 整月选择器，一次全量 |
| 保存后 | 返回上一页 | 留在原页（适合连续记账） |
| 截断 | 首页最多 50 条 | 无截断 |

## 7. 建议采纳的三点

1. **记账页底部加"最近 5 笔"预览** —— 记完立刻能确认，不用切页；这是一木首页最大的体验优势
2. **账单页改 30 天窗口 + 上拉加载** —— 现在选月份一次拉全量，账单多了会卡
3. **保存后留在原页（保持现状）** —— 一木返回上一页的设计在连续记账时更慢，我们这点更好，不要改
