迁移工具的安全边界：
- 退款/报销只继承「账单上已有的账本」

- 重复期号、引用缺失**只报告，不删除**

## 四、明确未做（诚实列出）

1. **双真机验收**：所有同步/周期/权限验证都是隔离模拟设备状态，未在两台真机跑过
2. **历史数据未实际迁移**：工具已就绪，但未对线上 565 条记录执行；`bookId` 缺失的历史记录仍走保守路径
3. **被改写的「其他」分类账单**：没有恢复脚本（需要人工核对哪笔是收入、哪笔是支出）
4. **期号冲突后的客户端处理**：服务端会拒绝重复期，但客户端目前靠已有的 `dedupeCycleBills` 收敛，没有"期号被拒 → 本地候选项作废"的显式回执
5. **旧接口删除的兼容性**：客户端已不用，但若有外部脚本调用会 404
6. **store.ts 仍有 850 行**：已抽 3 个 domain 模块，未按域彻底拆分
